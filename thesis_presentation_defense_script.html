⏱️ 0:25 - 0:55 (30 วินาที)
🗣️ คำพูดบรรยายที่ต้องพูด:
"ที่มาและความสำคัญของปัญหา เกิดจากการที่อาคารเรียนมักพบปัญหา 'การเปิดเครื่องปรับอากาศและไฟทิ้งไว้ในห้องเรียนที่ไม่มีผู้ใช้งาน' หลังเลิกเรียนครับ ซึ่งส่งผลกระทบต่อการสูญเสียพลังงานของอาคารอย่างมาก

ปัญหาสำคัญ 3 ประการคือ:
1. ไม่ทราบเวลาใช้งานจริง: ขาดระบบบันทึกชั่วโมงการเปิด-ปิดจริง ทำให้ไม่รู้ว่าถูกเปิดทิ้งไว้กี่ชั่วโมงกี่นาที
2. ข้อจำกัดการเดินตรวจ: แม่บ้านหรือ รปภ. ไม่สามารถเดินตรวจเช็กได้ตลอดเวลา ทำให้แอร์อาจเปิดทิ้งไว้นาน 1 ถึง 3 ชั่วโมงก่อนจะมีคนมาพบ
3. IoT & Automation: จึงเป็นที่มาของการนำเทคโนโลยี IoT มาตรวจจับสถานะเปิด-ปิดจริง และแจ้งเตือนผ่าน LINE อัตโนมัติครับ"

สไลด์ที่ 7
สถาปัตยกรรมระบบ 3 ชั้น (3-Tier System Architecture)
⏱️ 2:45 - 3:15 (30 วินาที)
🗣️ คำพูดบรรยายที่ต้องพูด:
"สถาปัตยกรรมระบบได้รับการออกแบบเป็น 3 ชั้น (3-Tier Architecture) เพื่อให้ระบบทำงานเป็นอิสระและมีความเสถียรสูงครับ:
1. Sensing Layer: บอร์ด ESP32 ต่อร่วมกับ DS18B20 วัดลมแอร์, PIR วัดคน, DHT22 วัดอุณหภูมิห้อง และ LDR วัดแสงสว่าง
2. Network & Server Layer: เชื่อมต่อผ่าน Wi-Fi ภายในอาคาร ส่งข้อมูลเข้า Apache Web Server ประมวลผลด้วย PHP และจัดเก็บลง MySQL Database
3. Presentation Layer: แสดงผลผ่าน Responsive Web App ด้วย Bootstrap 5, กราฟ Chart.js และส่งแจ้งเตือนผ่าน LINE Messaging API ครับ"

"กราบเรียนท่านคณะกรรมการครับ ในช่วงเริ่มต้นการออกแบบโครงงาน ทางกลุ่มเคยตั้งแนวคิดว่าจะประมาณการเป็นค่า kWh และเงินบาทครับ แต่เมื่อลงมือศึกษาและติดตั้งอุปกรณ์ในอาคารเรียนจริง เราพบประเด็นสำคัญ 2 ประการ:
1. ความปลอดภัยของอาคาร: การวัด kWh ที่ถูกต้องตามหลักวิศวกรรมไฟฟ้า ต้องติดตั้งหม้อแปลงวัดกระแส (CT Sensor) เข้ากับสายไฟเมนแรงดันสูง 220V ของเครื่องปรับอากาศ ซึ่งมีความเสี่ยงไฟฟ้าลัดวงจรและผิดระเบียบของอาคารสถานที่
2. ความถูกต้องทางวิทยาศาสตร์: เครื่องปรับอากาศในปัจจุบันเป็นระบบ Inverter ซึ่งกินกระแสไฟไม่คงที่ตลอดเวลา การนำจำนวนชั่วโมงไปคูณกับตัวเลขสเปกวัตต์เฉย ๆ จะได้ค่าที่คลาดเคลื่อนและไม่ใช่ค่าไฟจริง

ทางกลุ่มจึงเลือกใช้วิธี Non-invasive ที่ปลอดภัย โดยใช้เซนเซอร์วัดอุณหภูมิลมเย็น เพื่อตรวจสอบสถานะเปิด-ปิดจริง และบันทึกเวลาเป็น 'ชั่วโมงและนาทีการทำงานจริง (Operating Hours)' ตามวัตถุประสงค์ข้อ 3 ซึ่งแม่นยำ ปลอดภัย และตอบโจทย์การลดการเปิดแอร์ทิ้งไว้ได้อย่างแท้จริงครับ"
Q2 ทำไมถึงเลือกเกณฑ์อุณหภูมิ 26 องศาเซลเซียส (Threshold)? ทำไมไม่ใช้ 24 หรือ 25?
แนวทางการตอบ: อ้างอิงจากผลการทดลองหน้างานจริง (Empirical Data) ที่ห้อง SC2-307
"เกณฑ์ 26 องศาเซลเซียส ได้มาจากการเก็บข้อมูลจริงที่ห้อง SC2-307 ครับ โดยพบว่า:
• ในสภาวะที่ ปิดแอร์: อุณหภูมิอากาศบริเวณช่องลมแอร์จะเท่ากับอุณหภูมิห้อง ซึ่งเฉลี่ยอยู่ที่ 28 - 32 องศาเซลเซียส
• เมื่อ เปิดแอร์: คอยล์เย็นจะปล่อยลมออกมาที่อุณหภูมิประมาณ 18 - 24 องศาเซลเซียสอย่างรวดเร็วภายใน 1-2 นาที

ดังนั้น ค่า 26.0 องศาเซลเซียส จึงเป็นจุดตัด (Threshold) ที่มีความเสถียรสูงสุด ไม่ตัดเร็วเกินไปขณะแอร์เริ่มเดินเครื่อง และไม่ได้รับผลกระทบจากอุณหภูมิภายนอกห้องครับ"
Q3 เซนเซอร์ PIR มีจุดอ่อนคือจับคนอยู่นิ่งไม่ได้ แล้วทำไมไม่ใช้กล้อง AI หรือเซนเซอร์อื่น?
แนวทางการตอบ: อธิบายเรื่อง Privacy (ความเป็นส่วนตัว), ต้นทุน, พลังงาน และการแก้ปัญหาด้วย Debounce
"เหตุผลที่ไม่ใช้กล้อง AI ตรวจจับคนมี 3 ข้อหลักครับ:
1. สิทธิส่วนบุคคล (PDPA & Privacy): การติดกล้องในห้องเรียนอาจกระทบสิทธิของอาจารย์และนิสิต แต่เซนเซอร์ PIR ตรวจจับเพียงรังสีความร้อน ไม่มีการบันทึกภาพใด ๆ
2. ต้นทุนและพลังงาน: PIR ราคาประหยัดและกินไฟต่ำมาก สามารถทำงานได้ 24 ชั่วโมงโดยไม่ต้องใช้การ์ดจอประมวลผลสูง
3. การแก้จุดอ่อน: ทางกลุ่มได้แก้ปัญหาคนนั่งนิ่ง ๆ ด้วยการเขียนกลไก Debounce หน่วงเวลา 5 นาที บนฐานข้อมูล เพื่อเช็คว่าถ้าไม่มีการขยับตัวต่อเนื่องเกิน 5 นาทีจริง ๆ ถึงจะเริ่มนับเป็นห้องว่างครับ และในอนาคตสามารถต่อยอดเป็น mmWave Radar ได้ครับ"
Q4 กลไก Debounce 5 นาทีทำงานอย่างไรในโค้ด?
แนวทางการตอบ: อธิบายคำสั่ง SQL ในหน้า `insert_data.php` หรือ Backend PHP
"กลไก Debounce ทำงานที่ฝั่งเซิร์ฟเวอร์ PHP ครับ โดยเมื่อมีข้อมูลใหม่ส่งเข้ามา แทนที่ระบบจะดูแค่ค่า PIR ของวินาทีนั้น ระบบจะสั่งคิวรี่ SQL ย้อนหลัง 300 วินาที (5 นาที):
SELECT MAX(motion_status) FROM sensor_logs WHERE room_id = ? AND created_at >= NOW() - INTERVAL 5 MINUTE
หากค่า MAX เป็น 1 แสดงว่าในช่วง 5 นาทีที่ผ่านมาเคยมีการเคลื่อนไหว ระบบจะยังถือว่ามีคนอยู่ในห้อง เพื่อป้องกัน False Alarm ครับ"
Q5 ทำไมบอร์ด ESP32 ถึงส่งข้อมูลด้วย HTTP POST ทำไมไม่ใช้ MQTT Protocol?
แนวทางการตอบ: อธิบายเรื่อง Architecture ความเรียบง่าย และการเชื่อมต่อกับ Apache/PHP โดยตรง
"เนื่องจากสถาปัตยกรรมระบบของเราใช้ Apache Web Server และ PHP ซึ่งทำงานกับ HTTP เป็นมาตรฐานอยู่แล้วครับ การใช้ HTTP POST ช่วยให้:
1. บอร์ด ESP32 สามารถยิงข้อมูลเข้าสู่สคริปต์ insert_data.php เพื่อตรวจสอบความถูกต้องและบันทึกลง MySQL ได้ทันทีในคำสั่งเดียว
2. ลดความซับซ้อน ไม่ต้องติดตั้งและดูแล MQTT Broker เพิ่มเติมในฝั่งเซิร์ฟเวอร์
3. ความถี่การส่งข้อมูลอยู่ที่ทุก ๆ 5 วินาที ซึ่งโปรโตคอล HTTP สามารถรองรับได้อย่างเสถียรโดยไม่เกิดปัญหาคอขวดครับ"
Q6 การคำนวณชั่วโมงและนาทีสะสมในหน้ารายงาน (report.html) คำนวณอย่างไร?
แนวทางการตอบ: อธิบาย Logic ของ `energy_api.php`
"ในหน้า Backend energy_api.php จะดึงข้อมูลจากตาราง sensor_logs โดยนับจำนวนแถวของข้อมูลที่มีสถานะแอร์เปิด (ac_status = 1) ในช่วงวันที่ต้องการ
เนื่องจาก ESP32 ส่งข้อมูลทุก 5 วินาที เราจึงนำจำนวนแถวมาคำนวณเวลาสะสมเป็นวินาที แล้วแปลงเป็น 'ชั่วโมง' และ 'นาที' เพื่อส่งกลับเป็น JSON ไปแสดงผลบน Summary Card และพล็อตกราฟแท่ง Chart.js ครับ"
Q7 ระบบจับคู่ตารางสอน (Schedule Matching) มีตรรกะการตรวจสอบอย่างไร?
แนวทางการตอบ: เปรียบเทียบวันและเวลาปัจจุบัน (Current Timestamp) กับตาราง `schedule`
"เมื่อเซิร์ฟเวอร์ได้รับข้อมูลจากห้อง SC2-307 ระบบจะดึงวันในสัปดาห์ (เช่น วันจันทร์) และเวลาปัจจุบัน (เช่น 10:15 น.) ไปเทียบกับตาราง schedule:
• ถ้าเวลาปัจจุบันอยู่ในช่วง start_time ถึง end_time ของวิชาที่ลงทะเบียนไว้ ระบบจะรับรู้ว่าช่วงเวลานี้ 'มีวิชาเรียนตามตาราง'
• ซึ่งช่วยให้ระบบไม่แจ้งเตือนผิดพลาดในกรณีที่อาจารย์กำลังบรรยายหน้าชั้นเรียนแต่นิสิตนั่งฟังนิ่ง ๆ ครับ"
Q8 ผลการทดสอบ 15 ครั้ง ทำไมถึงได้ความแม่นยำ 86.67%? ข้อผิดพลาด 2 ครั้งเกิดจากอะไร?
แนวทางการตอบ: ตอบอย่างซื่อสัตย์ตามบทที่ 4 (หน้า 94-95)
"จากการทดสอบตามสถานการณ์จำลอง 15 ครั้ง ถูกต้อง 13 ครั้ง คิดเป็น 86.67% โดยแยกเป็น:
• กรณีห้องว่าง (No use): ถูกต้อง 100% (5/5 ครั้ง)
• กรณีใช้งานปกติ (In Use): ถูกต้อง 80% (4/5 ครั้ง) มี 1 ครั้งที่นิสิตนั่งนิ่งเกิน 5 นาที ทำให้เซนเซอร์ PIR ไม่จับสัญญาณ
• กรณีเปิดแอร์ทิ้งไว้ (Warning): ถูกต้อง 80% (4/5 ครั้ง) มี 1 ครั้งที่เซนเซอร์ PIR ได้รับสัญญาณรบกวนชั่วขณะ ทำให้ระบบประเมินว่ามีคน
ซึ่งผลทดสอบยืนยันว่าระบบมีความแม่นยำเพียงพอในการตรวจจับและลดการเปิดเครื่องใช้ไฟฟ้าทิ้งไว้ได้อย่างมีประสิทธิภาพครับ"
Q9 แสงแดดภายนอกส่งผลกระทบต่อการวัดสถานะไฟของเซนเซอร์ LDR หรือไม่?
แนวทางการตอบ: ยอมรับข้อจำกัดตามบทที่ 5 และอธิบายการปรับจูน Threshold
"ส่งผลกระทบได้ครับ ในห้องเรียนที่มีหน้าต่างรับแสงธรรมชาติ หากเป็นช่วงเวลากลางวันที่มีแดดจัด ค่าความสว่างที่วัดได้อาจสูงขึ้น ทางกลุ่มจึงแก้ไขโดยการปรับตัวต้านทานปรับค่าได้ (Trimmer Potentiometer) บนโมดูล LDR เพื่อกำหนดค่าเกณฑ์ความสว่างให้สอดคล้องกับความสว่างของหลอดไฟฟลูออเรสเซนต์ในห้อง และระบุข้อจำกัดนี้ไว้ในบทที่ 5 เรียบร้อยแล้วครับ"
Q10 ถ้าสัญญาณ Wi-Fi หลุด หรือไฟดับ ระบบจะมีพฤติกรรมการทำงานอย่างไร?
แนวทางการตอบ: อธิบายฟังก์ชัน Reconnect ของ ESP32 และหน้า Device Status
"ในโค้ดของบอร์ด ESP32 มีคำสั่งตรวจสอบสถานะ WiFi.status() != WL_CONNECTED หากสัญญาณหลุด บอร์ดจะพยายาม Reconnect เชื่อมต่อใหม่อัตโนมัติโดยไม่ต้องรีเซ็ตเครื่องครับ
ส่วนฝั่งหน้าเว็บ เรามีหน้า Device Health Check ซึ่งตรวจสอบว่าบอร์ดมีการส่งข้อมูลเข้ามาล่าสุดเมื่อใด หากไม่มีข้อมูลส่งเข้ามาเกิน 1 นาที ระบบจะขึ้นสถานะว่า 'Offline' เพื่อแจ้งเตือนให้ผู้ดูแลทราบทันทีครับ"
Q11 ทำไมระบบไม่สั่งปิดแอร์อัตโนมัติไปเลย เมื่อตรวจพบสถานะ Warning?
แนวทางการตอบ: อธิบายเรื่อง Safety และสิทธิ์การตัดสินใจของผู้ใช้งาน
"มี 2 เหตุผลหลักครับ:
1. ความปลอดภัยและผลกระทบต่อการเรียนการสอน: ในกรณีที่มีนิสิตกำลังสอบ หรือทำแล็บอยู่นิ่ง ๆ การที่ระบบตัดแอร์อัตโนมัติอาจสร้างความเสียหายหรือรบกวนการเรียนได้ การแจ้งเตือนให้เจ้าหน้าที่รับทราบก่อนถือเป็นแนวทางที่ปลอดภัยที่สุด
2. การควบคุมแอร์: การสั่งปิดแอร์ต้องติดตั้งชุดส่งสัญญาณอินฟราเรด (IR Transmitter) เพิ่มเติม ซึ่งเราได้วางแผนไว้เป็นแนวทางการพัฒนาต่อยอดในเฟสถัดไปครับ"
Q12 ถ้าอนาคตจะนำไปติดตั้งจริงทั่วทั้งมหาวิทยาลัย 100 ห้อง ระบบจะรองรับไหวไหม?
แนวทางการตอบ: อธิบายเรื่อง Scalability, Database Indexing และการปรับความถี่
"สถาปัตยกรรมที่เราออกแบบไว้รองรับการขยายตัว (Scalability) ได้เป็นอย่างดีครับ:
1. ในฐานข้อมูล sensor_logs ได้มีการสร้าง Index บนคอลัมน์ room_id และ created_at ทำให้คิวรี่ได้อย่างรวดเร็วแม้ข้อมูลจะมีหลายแสนแถว
2. หากมี 100 ห้อง เราสามารถปรับลดความถี่ในการส่งข้อมูลของ ESP32 จากทุก 5 วินาที เป็นทุก 30 วินาที หรือ 1 นาที ซึ่งจะลดภาระของเซิร์ฟเวอร์ลงได้ถึง 6-12 เท่า โดยที่ยังคงประสิทธิภาพการตรวจจับสถานะได้อย่างสมบูรณ์ครับ"
⚙️ แผนผังทางเทคนิคและ API Reference

ข้อมูลจำเพาะเชิงลึกของฮาร์ดแวร์ พินเชื่อมต่อ ตารางฐานข้อมูล และ API Endpoint

1. ข้อมูลจำเพาะของเซนเซอร์และพินเชื่อมต่อ (Hardware Pinout)
อุปกรณ์ / เซนเซอร์ โมเดล / รุ่น ขาเชื่อมต่อ ESP32 บทบาทหน้าที่
ไมโครคอนโทรลเลอร์ ESP32 DevKit V1 (30 pins) - ประมวลผลและส่งข้อมูลผ่าน Wi-Fi 2.4 GHz
เซนเซอร์วัดลมแอร์ DS18B20 (Waterproof Probe) GPIO 4 (1-Wire Bus) ตรวจวัดอุณหภูมิลมเย็นหน้ากากแอร์ (≤ 26°C)
เซนเซอร์ตรวจจับคน HC-SR501 PIR Motion Sensor GPIO 13 (Digital In) ตรวจจับรังสีความร้อนจากการเคลื่อนไหว
เซนเซอร์วัดสภาพห้อง DHT22 (AM2302) GPIO 14 (Digital In) วัดอุณหภูมิห้อง (°C) และความชื้นสัมพัทธ์ (%RH)
เซนเซอร์วัดแสงสว่าง LDR Sensor Module GPIO 27 (Digital In) ตรวจสอบสถานะการเปิด-ปิดหลอดไฟในห้อง
2. API Endpoints และโฟลว์ข้อมูล (Data Flow)
1. บอร์ด ESP32 -> Web Server:
   Endpoint: POST http://[Server-IP]/smart_classroom/insert_data.php
   Payload (x-www-form-urlencoded):
   room_id=1&temp=28.5&humidity=60.2&light=1&motion=1&ac_temp=22.4

2. Web Frontend -> API:
   - GET get_data.php      : ดึงสถานะ Real-time ล่าสุดมาอัปเดตหน้า Dashboard
   - GET energy_api.php    : สรุปผลชั่วโมงการใช้งานแอร์สะสม (ชั่วโมง : นาที)
   - POST upload_schedule.php : อัปโหลดไฟล์ Excel ตารางสอน (.xlsx)
   - POST send_line_alert.php : สั่งส่งข้อความแจ้งเตือนเข้าแอปพลิเคชัน LINE
